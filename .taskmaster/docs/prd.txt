# Overview

Doctor Subs v2 is a WooCommerce Subscriptions diagnostic + one-click fix plugin for WordPress, shipped on the WP.org plugin directory. It helps non-technical store owners (20-500 subscriptions) detect and repair three specific broken-subscription patterns without needing to read logs, open a support ticket, or hire a developer.

Primary user: solo, non-technical store owner in panic mode when revenue dips or a customer complains. Secondary user: agency developer managing multiple client stores. The plugin lives inside /wp-admin/ as a menu item under WooCommerce.

v1.2.4 exists on WP.org today with a 3-step diagnostic UI that assumes log-reading skill and does not actually fix anything. v2 is a full rewrite that:
- Detects 3 specific high-confidence broken-subscription patterns
- Fixes them with one-click preview + reversible journal
- Scans the whole store daily in the background
- Alerts the admin via email when something new breaks
- Ships in 20 major languages via AI-translated .po/.mo files

# Core Features

## 1. Traffic-light dashboard (the primary surface)
Three counter cards - Healthy / At risk / Broken - with plain-English reasons in a "Needs attention" table. Counters are clickable filters. Every row has a Fix button that opens the preview modal.

## 2. Three detection rules (v1 scope)
- **Ghost Sub (high confidence)**: active status + past next_payment + no pending Action Scheduler event. Fix: re-enqueue the AS payment event.
- **On-hold with paid renewal (Stripe only in v1)**: sub is on-hold + latest renewal order has `_stripe_charge_captured` meta. Fix: flip order to completed + sub to active.
- **Repeated AS failures (medium confidence)**: >=2 failed `woocommerce_scheduled_subscription_payment` actions for this sub in last 30 days. Fix: retry the latest failed action once (no loop).

Each rule ships as its own class implementing:
- `detect_batch(array $sub_ids, ScanContext $ctx): RuleMatch[]`
- `preview_fix(WC_Subscription $sub): FixPreview`
- `apply_fix(WC_Subscription $sub): FixResult` (state-guarded via allow-listed field compare)
- `revert_fix(FixJournalEntry $entry): RevertResult` (with already-executed-AS warning)
- `template(RuleMatch $match): string` (narrator, no AI)

## 3. Background scanner
Scheduled via Action Scheduler (recurring action `dr_subs_daily_health_scan`) with a WP-Cron watchdog (`dr_subs_cron_watchdog`) hourly that triggers if AS missed >36h. Builds a shared ScanContext once per run (pending AS events grouped by sub_id, failed AS events in last 30d grouped by sub_id) so rules query O(1) not N+1. Iterates active subs in batches of 100. Writes one row per sub to `dr_subs_sub_health`. Generates narrator output at scan time and persists on the health row.

## 4. Fix journal with revert
Every applied fix is a journaled transaction. Schema: timestamp, sub_id, rule_id, batch_id, before_state (JSON of fields the rule will change), before_state_hash (sha256 for state-guard), after_state (JSON), side_effects (JSON list including hook+args+id for AS revert), user_id, status (applied/reverted). Apply is state-guarded: rule declares allow-listed fields (e.g. Ghost Sub declares ['status','next_payment']) and apply aborts if current state != before_state on those fields. Revert checks state drift and warns before applying. Already-executed AS action special case: revert shows explicit modal warning ("the payment already went through...").

## 5. Daily email digest
When scanner completion detects new broken subs since last run, sends a digest email. Configurable via settings (enabled/disabled, target email, defaults to admin_email). Respects a `suppressed_until` column on `dr_subs_sub_health` so acknowledged-broken subs don't re-nag.

## 6. Bulk fix UI
"Fix all N ghost subs" button on dashboard. Invokes rule's batch apply variant, all fixes share a `batch_id`, revert entire batch atomically.

## 7. Settings page
Three sections: Alerts (toggle + email field), Fix history retention (30/90/180/365/forever), Help us improve (anonymous telemetry toggle, off by default). AJAX-saved with Saving.../Saved. flash. Unsaved-changes guard via JS.

## 8. Translations
Ship in 20 major languages via Potomatic (AI-translated .po/.mo files). Workflow: `wp i18n make-pot` generates the canonical .pot, Potomatic translates to target locales using an LLM, `wp i18n make-json` compiles .po to .mo.

# Technical Architecture

## Class rename (breaking)
v2 renames all PHP classes from `WCST_*` to `DR_Subs_*`. Public filter/hook prefix renames `wcst_*` to `dr_subs_*`. Constant rename `WCST_PLUGIN_*` to `DR_SUBS_PLUGIN_*`. Single breaking moment in v2.0 instead of carrying old prefix forever.

## Core classes (new in v2)

- `DR_Subs_Plugin` - main bootstrap (replaces WCST_Plugin)
- `DR_Subs_Admin` - admin interface router + enqueue (replaces WCST_Admin, with tab-based routing to the 5 surfaces)
- `DR_Subs_AJAX_Handler` - handles `dr_subs_get_fix_preview`, `dr_subs_apply_fix`, `dr_subs_revert_fix`, `dr_subs_run_scan`, `dr_subs_cancel_scan`, `dr_subs_save_settings` (all with nonce + capability check)
- `DR_Subs_Security` - keeps existing nonce/capability helpers (renamed from WCST_Security)
- `DR_Subs_Migration` - activation-hook migration: creates `dr_subs_sub_health` + `dr_subs_fix_journal` custom tables via dbDelta, preserves existing `wcst_settings` option data by reading and rewriting as `dr_subs_settings`

## Rules engine

- `DR_Subs_Rule_Interface` - contract: detect_batch, preview_fix, apply_fix, revert_fix, tracked_fields (allow-list for state guard), narrate
- `DR_Subs_Rules_Registry` - registers/enumerates rules; exposes `dr_subs_detection_rules` filter for third-party rule plugins
- `DR_Subs_Rule_Ghost_Sub` - ghost-sub rule impl
- `DR_Subs_Rule_On_Hold_Paid` - Stripe on-hold-with-paid rule impl
- `DR_Subs_Rule_Repeated_Failures` - repeated AS failures rule impl
- `DR_Subs_Rule_Match` - lightweight DTO (rule_id, sub_id, severity, context data, cached narration text)
- `DR_Subs_Scan_Context` - pre-scan index container (pending_as_by_sub, failed_as_by_sub last 30d, related_orders_by_sub)

## Scanner + journal

- `DR_Subs_Health_Scanner` - run(): build ScanContext, iterate subs in batches, apply rules, upsert `dr_subs_sub_health`, narrate each match, fire `dr_subs_after_scan` action
- `DR_Subs_Fix_Journal` - record(FixJournalEntry), revert(entry_id), purge_older_than(days)
- `DR_Subs_Narrator` - selects a template variant per rule + substitutes vars (sub_id, customer_name, dates)
- `DR_Subs_Alert_Dispatcher` - listens on `dr_subs_after_scan`, composes digest, sends via wp_mail to `dr_subs_settings.alert_email || admin_email`

## Data model

### Table `dr_subs_sub_health`
- sub_id BIGINT UNSIGNED PK
- bucket VARCHAR(20) NOT NULL ('healthy'|'at_risk'|'broken')
- matched_rules JSON (array of {rule_id, severity})
- narration TEXT NULL (populated by scanner at scan time)
- last_scanned_at DATETIME NOT NULL
- suppressed_until DATETIME NULL
- Index: (bucket, last_scanned_at DESC) composite; (bucket) alone for COUNT aggregation

### Table `dr_subs_fix_journal`
- entry_id BIGINT UNSIGNED AUTO_INCREMENT PK
- batch_id VARCHAR(40) NULL
- sub_id BIGINT UNSIGNED NOT NULL
- rule_id VARCHAR(60) NOT NULL
- before_state JSON NOT NULL
- before_state_hash CHAR(64) NOT NULL
- after_state JSON NOT NULL
- side_effects JSON NOT NULL (e.g. [{type:'as_action', hook, args, id}, {type:'order_status_change', order_id, from, to}])
- user_id BIGINT UNSIGNED NOT NULL
- status ENUM('applied','reverted') NOT NULL DEFAULT 'applied'
- created_at DATETIME NOT NULL
- reverted_at DATETIME NULL
- Indexes: (sub_id, created_at DESC); (batch_id)

### Option `dr_subs_settings`
- alerts_enabled (bool, default true)
- alert_email (string, default admin_email)
- journal_retention_days (int, default 180; -1 = forever)
- telemetry_enabled (bool, default false)

## Integration points (public API)

- Filter: `dr_subs_detection_rules` - register custom rule classes
- Action: `dr_subs_before_scan` - fires at scanner start
- Action: `dr_subs_after_scan` - fires at scanner completion with ScanSummary
- Action: `dr_subs_before_fix_apply` - fires pre-apply with sub + rule_id
- Action: `dr_subs_after_fix_apply` - fires post-apply with FixJournalEntry
- Filter: `dr_subs_narration` - decorate narrator output
- AS hook: `dr_subs_daily_health_scan` - the recurring scanner
- WP-Cron hook: `dr_subs_cron_watchdog` - AS watchdog

# Logical Dependency Chain

1. Phase 1 Foundation MUST complete first - everything else depends on the renamed classes, tables, and wired assets.
2. Phase 2 Rules Engine can start after Phase 1. Each rule is independent of the others once the interface and ScanContext exist, so three rules can be written in parallel within Phase 2.
3. Phase 3 Scanner + Journal + Narrator depends on Phase 2 rules existing. Journal is technically independent but revert() needs to call rules' revert_fix().
4. Phase 4 AJAX + wiring depends on Phase 3 data existing (otherwise the dashboard renders empty forever).
5. Phase 5 Bulk fix + cleanup + telemetry depends on Phase 3 + Phase 4 being complete.
6. Phase 6 Translations can run in parallel with Phase 5 (different files touched). POT generation needs Phase 1-4 strings to be final.
7. Phase 7 QA + ship is last, depends on everything.

Critical "first visible thing that works" path for motivation: Phase 1 foundation + Phase 2 Ghost Sub rule + enough of Phase 3 to have a scanner run manually + enough of Phase 4 to render the dashboard. That's the vertical slice that proves the whole architecture.

# Risks and Mitigations

## Scanner performance on large stores (5k+ subs)
v1.2.4 uses N+1 `args LIKE '%sub_id%'` queries per sub which is fatal at scale. v2 ScanContext builds one indexed query per hook and buckets in PHP. Mitigation: seeded 5000-sub stress test before v2.0.0 ships (Phase 7).

## Font licensing + WP.org plugin directory compliance
WP.org forbids runtime fetches of external assets. Fonts already self-hosted in design-brief/v2-assets/admin/fonts/ under OFL (JetBrains Mono, Instrument Serif) and Fontshare free tier (Switzer) - all permit self-hosting. Mitigation: documented in v2-assets/README.md; add attribution to plugin readme.txt license section.

## HPOS-only baseline drops some CPT stores
Eng review decision accepted this tradeoff. WCS 9.x stores are nearly all HPOS by 2026. Mitigation: bump WC requirement to 9.0+ in plugin header, show admin notice on activation if WC < 9.0.

## Revert-of-already-executed AS action UX
Originally overridden to silent no-op; design phase reversed back to explicit warning. Modal template renders an $already_executed warning block when the AS action has already run. Mitigation: scanner's ScanContext tracks executed AS status; ajax_handler passes flag through to modal template.

## Sub ID substring match bug (CRITICAL REGRESSION)
v1.2.4 uses `args LIKE '%11%'` which matches sub IDs 1, 11, 111, etc. v2 must use proper unserialize + exact compare. Mitigation: regression test seeded with subs 1, 11, 111, 110 asserts exact-one-match. Written in Phase 2.

## Monthly renewals crossing February (CRITICAL REGRESSION)
v1.2.4 `get_billing_period_days` treats month as 30 days. Feb renewals flag as "skipped". v2 must use DateTime::modify('+1 month'). Mitigation: regression test seeded Jan-31 monthly renewal asserts no false skipped-cycle on Feb 28 -> Mar 31 interval. Written in Phase 2.

## Translation accuracy via AI
Potomatic uses LLM; output varies. Brand terms must not be translated. Mitigation: user dictionary in `config/dictionaries/dictionary.json` lists "Doctor Subs", "WooCommerce", "WordPress", "Stripe", "Action Scheduler", "PayPal", "Subscription" as no-translate terms. After first generation, review at least the 5 most-used languages (fr/es/de/it/pt) manually before shipping.

## Admin notice on activation if WCS missing
Existing v1.2.4 logic handles this. Port to v2 in Phase 1.

## Class rename breaks third-party plugins extending Doctor Subs
Unlikely for a plugin this size but possible. Mitigation: publish migration note in WP.org support forum + add class_alias shims for the 3 most-likely-extended classes (WCST_Plugin, WCST_Admin, WCST_AJAX_Handler) that log deprecation warnings for one release cycle.
